# workflow-kit

`workflow-kit` 是一个中文 AI 项目全链路总控 Skill，面向不会开发或不熟悉软件交付的人。它把一个想法、客户需求或接手项目，拆成需求澄清、价值判断、架构、执行分工、测试测评、手册反测和完整交付。

当前开发版本：`v3.7.1`（本地体验优化中，未发布）；已发布版本：[`v3.6.0`](https://github.com/xiujiayou888-xiuxiu/project-workflow/releases/tag/v3.6.0)

## 适合场景

- 把个人想法做成可运行、可验收的产品。
- 接客户项目时控制需求、报价、范围、风险和交付。
- 接手旧项目时先看懂、建立基线，再做最小安全改动。
- 开发前先判断能否参考或复用成熟开源项目、官方模板、SDK、组件和设计系统。
- 在 Codex、Claude、Cursor、ZCode 等多个 AI 工具之间保持同一套项目流程。

## 安装

### 方式一：使用发布包

1. 下载 Release 中的 `project-workflow-skill.zip`。
2. 解压后得到 `project-workflow/` 目录。
3. 将该目录放入你的 AI 工具或 Codex Skill 目录。
4. 在新会话中输入：

```text
使用 $project-workflow，我想做一个项目。
```

### 方式二：直接使用源码

读取仓库根目录的 `SKILL.md`，并按其中路由规则只加载需要的 `references/` 模块。

## 核心原则

- 先问清需求，再规划、开发或报价。
- 传统 App 每轮只问 1-3 个真正影响结果的问题；智能体或混合产品每轮最多问一个高影响决策。
- 全链路按 `基础版 -> 进阶版 -> 高阶版 -> 最终版` 逐级交付：基础版先完成可验收核心闭环，后续版本必须依据验收证据、真实反馈和用户确认推进。
- 当前版本确认开工后，当前 Agent 与可控子 Agent 连续执行到版本验收；只在高风险、边界不清或必须由用户决定的问题出现时再次确认。
- 先区分传统 App、智能体和混合产品：智能体必须围绕用户目标主动读取上下文、计划、调用工具、观察、修正并交付结果，不能把中间工作退回为表单填写。
- 智能体可由已批准目标、授权事件或定时计划主动运行，在边界内检查、执行、保存状态并汇报；高风险行动仍需单独确认。
- 智能体需求澄清先读取已有资料，回显目标、事实、推断、风险和推荐；每轮只问一个真正影响决策的问题，信息足够即直接进入已确认版本的连续执行。
- 首次使用只需说目标。AI 默认先给出理解、基础版建议和一个必要决定；PRD 与开工合并为一次版本确认，确认后不再逐步追问。
- 未经用户确认，AI 建议功能只记录为 `CAND-*`，不升级为正式需求。
- 高风险未知先做 POC，不假装已验证。
- 正式架构和编码前做开源参考与复用评估，记录 URL、许可证、版本/commit、证据、风险和采用结论。
- 任何项目都必须通过合法合规门禁：确认第三方权利、授权、隐私、数据来源和适用规则；不得侵权、违法或在疑点未解决时继续采用。
- 每一步都留下工具、输入、输出、保存路径和验收证据。
- 支持子 Agent 且经验证可并行的工具可多派发；单会话工具按任务实际需要串行分配，不预占。
- 每个派发任务都会生成独立的 `PAR-XXX-交接包.md`：把下一个 AI 实际需要的资料整理并内嵌在同一文件中，可直接打开、全选并复制；聊天也会显示相同内容。
- 文档不是完成，必须能对应到代码、页面、命令、URL、安装包或明确决策。
