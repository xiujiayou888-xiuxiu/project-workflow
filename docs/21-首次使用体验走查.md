# 21 首次使用体验走查

## 目的

以第一次使用 `workflow-kit` 的普通用户视角验证：用户只说目标时，系统是否能先理解、提出建议、只索取必要决定，并在一次版本确认后自行推进，而不是把用户带进表单、流程图或重复确认。

## 场景 A：要做主动型智能体

用户原话：`我想做一个每周自动整理客户访谈、给我风险提示和下一步建议的智能体。`

### 旧路径的摩擦

- 可能先出现项目路径、路由、产品形态、五个 Agent 问题和十步流程，用户看不到第一步能得到什么。
- 定时运行容易被提前拆成频率、时区、通知、暂停等设置表，用户尚未确认任务本身是否有价值。
- PRD 确认后再问一次“是否开工”，用户需要做两次本质相同的决定。

### 修复后的期望首轮

```text
我理解你希望每周自动获得“访谈结论 -> 风险 -> 下一步建议”，并且不想手工整理原始记录。

我建议基础版先接入一个已授权的访谈来源，每周生成一份可追溯摘要和风险清单；先不做跨系统自动写入或自动对外通知。

我已知：你需要定期汇总与建议。暂时推断：访谈记录可被授权读取。需要留意：来源权限和提醒渠道会影响是否能自动运行。

现在只需要你决定：基础版先读取哪一个现有来源？我建议先选最稳定、最常用的来源。
```

### 通过标准

- 首轮没有项目路径、路由、文档编号、工具等级、完整功能表或定时设置表。
- 用户只需决定一个会改变结果的事项。
- 资料来源、权限、基础版范围、验收和高风险边界明确后，出现一次版本开工确认卡；确认后不再追问“下一步”。
- 智能体完成基础版任务后，才根据实际重复价值建议定时计划。

## 场景 B：要做传统内部工具

用户原话：`客户资料太乱了，帮我做个给销售用的小工具。`

### 旧路径的摩擦

- 若一开始要求客户角色、权限、数据库、部署和完整功能清单，普通用户会不知道先回答什么。
- 传统 App 与智能体的问题混在一起，用户会误以为必须设置 AI、工具或定时任务。

### 修复后的期望首轮

```text
我理解你想让销售更快找到客户资料，减少在多个地方翻记录的时间。

我建议基础版先做“统一查看客户、最近跟进和下一步提醒”的一个闭环；先不做复杂权限、自动营销或多系统同步。

我暂时判断这是传统内部工具，不需要把它做成智能体。现在最影响基础版的是：销售目前最常从哪里找客户资料？
```

### 通过标准

- 系统先给可验收的基础版闭环和产品形态判断，而不是技术问卷。
- 只问一个决定核心数据入口的问题；其他字段由后续缺口驱动。
- 产品确认和开工确认合并为一次版本确认；确认后连续完成当前版本。

## 回归检查清单

- 首次回复是否包含理解、建议、事实/推断/风险和最多一个必要问题？
- 用户是否能自然语言纠正，而不必填写固定表？
- 是否只在授权、业务判断、高风险或真正阻塞时打断？
- PRD 与开工是否为同一次确认？
- 定时计划是否在产生明确重复价值后才建议，并有批准、暂停和取消入口？
- 用户是否始终能看到当前结果、证据和下一建议，而不必理解内部流程？
