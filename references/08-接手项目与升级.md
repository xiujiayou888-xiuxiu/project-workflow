# 08 接手项目、模块改造与升级安全

## 目标

先理解和运行，再修改。保护用户已有代码、数据、配置、部署和未提交改动；每个模块可独立修复、测试和升级。

## 接手拆解顺序

1. 读取 README、AGENTS/规则、脚本、环境示例、部署和升级说明。
2. 检查 Git 状态、分支、未提交改动和最近历史；不撤销未知改动。
3. 映射目录、前后端、数据库、任务、配置、测试和部署。
4. 找启动命令，在安全环境运行，记录基线 URL/输出/错误。
5. 映射主要用户流程、页面/命令、API/认证/权限和数据流。
6. 识别业务对象、真相来源、状态、文件/上传、第三方和人工环节。
7. 检查依赖、生成脚本、危险命令、测试、CI、日志、备份和回滚。
8. 对照原需求/实际行为，记录已知缺陷、技术债务和不可观察区域。
9. 选择最小安全变化，拒绝无必要全量重构。

保存 `docs/00-项目拆解报告.md`：路径、技术栈、启动、架构/模块、数据/API/页面流、权限、测试、部署、风险、可安全修改区和第一张卡。

## 别人项目/开源项目结构化拆解

当输入是别人的项目、开源项目、竞品仓库或可参考项目时，同时更新 `docs/02-开源参考与复用评估.md`。拆解目标是理解可复用资产和差异化机会，不是复制。

| 维度 | 必须记录 |
| --- | --- |
| 目标用户 | 项目服务谁、解决什么高频/高价值任务 |
| 核心旅程 | 从进入到完成结果的关键步骤和成功证据 |
| 模块边界 | 前端、后端、数据、任务、第三方、管理后台和共享模块 |
| 数据模型 | 业务对象、状态、所有权、保留/删除/导出 |
| 接口 | API、事件、任务、CLI、Webhook、权限边界 |
| 权限 | 角色、租户、敏感操作、审计和越权风险 |
| 部署 | 运行时、环境变量、数据库、存储、CI/CD、回滚 |
| 测试 | 单测、集成、E2E、示例数据、质量缺口 |
| 优缺点 | 适合场景、限制、技术债、维护风险 |
| 可复用部分 | 架构、交互、组件、SDK、数据结构、测试策略等 |
| 不能复制部分 | 许可证不兼容、品牌、商业秘密、用户数据、来源不明代码、脆弱实现 |
| 差异化机会 | 本项目应保留的独特定位、流程、数据和体验 |

采用任何代码前先检查许可证、NOTICE/署名、版本/commit、依赖和安全风险。默认只参考公开架构/交互和成熟组件；禁止整库照搬或把项目包装成自有原创。

## 变化边界

修改前声明：目标、关联 REQ/缺陷、允许/禁止文件、契约、数据/迁移影响、测试、回滚和任务锁。

若任务需要超范围或改共享契约，停止并交总控更新 ADR、卡片和计划。不要顺手清理、改名、升级依赖或重构无关代码。

## 模块契约

创建/更新 `docs/26-模块契约与升级方案.md`：

| MOD-ID | 目的 | 目录/所有者 | 公开契约 | 拥有数据 | 允许依赖 | 禁止依赖 | 独立测试 | 兼容/迁移 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

规则：

- 模块通过公开接口通信，不直接改他人表/文件/内部状态。
- 认证、数据库迁移、共享类型/API、公共组件接口、环境和部署由总控唯一拥有。
- 功能卡写入独占模块范围；独立测试通过后才集成。
- 共享工具只承载真正稳定通用逻辑，避免“万能 utils”。

## V2+ 升级不清数据

- 分离程序、用户数据、上传、日志、缓存、密钥和配置。
- 安装程序只替换程序文件；数据目录默认保留。
- 使用版本号和幂等迁移，记录已执行版本。
- 迁移前备份并验证可读取；迁移后校验数量、关键字段、权限和核心流程。
- 用代表性 V1 数据测试 V1 -> V2，不用空白安装代替升级测试。
- 失败有恢复/回滚；破坏性格式变化有过渡适配或导入导出。
- 旧配置缺新字段时有安全默认和清晰提示，不重置全部配置。
- 同版本重复安装/迁移安全。

## 旧项目接入 V3 Skill

读取旧 `项目状态.md`、路径索引和链接，不删除旧文档。给旧文档建立 V3 对应表；事实以已有证据为准。写 `workflow_schema: project-workflow-v3`，只在需要继续维护时生成新简化文档。

Skill 更新只替换 Skill/reference 文件，永不删除 `PROJECT_ROOT`、源码、数据库、上传、用户配置或其他 Skill。

## 接手/升级门禁

- 运行基线可复现或阻塞明确。
- 未提交/用户改动被保护。
- 数据、权限、契约和部署边界清楚。
- 最小变更、测试和回滚明确。
- 数据升级有备份、迁移、校验和恢复证据。
- 修复/升级后旧核心流程和新需求都通过。
