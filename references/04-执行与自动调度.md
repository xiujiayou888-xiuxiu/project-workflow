# 04 执行与自动调度

## 目标

把“建议用某工具”变成可执行、可监控、可接手、可验收的任务。总控是唯一状态和合并负责人。

## 非破坏性工具扫描

保存到 `docs/00-项目路由与能力扫描.md`：

- 终端/工作区 AI：Codex、Claude Code、ZCode、Aider 等。
- IDE：Cursor、VS Code、Windsurf 等。
- Git、Node/npm/pnpm、Python、Docker 和项目已有运行时。
- 浏览器、Playwright、截图、API/测试、安全/性能工具。
- Figma/设计 MCP、UI/审美 Skill、图像搜索/生成。
- GitHub、Notion/Linear/本地 Markdown 和部署平台能力。
- 子 Agent、任务、独立会话、分支/工作树和项目路径访问。
- 安装状态、版本、登录/授权/付费、可控制性和替代方案。

状态只用：`已检测可用 / 已检测但需登录授权 / 浏览器可用待确认 / 未检测 / 无法观察`。

不得因为公开网站存在就说账号可用；不得因为模型聪明就说有子 Agent。

## A0-A4 能力证明

逐项记录 yes/no/unknown：创建、分配、独立上下文、真实并行、隔离写入、D 盘访问、状态/等待/取消、证据回传、专项工具控制和成本可见。

| 等级 | 证明 | 自动行为 |
| --- | --- | --- |
| A0 | 无法创建/控制工作者 | 总控单线；必要时人工外派 |
| A1 | 可创建但隔离未知 | 只读分析/审查；总控应用结果 |
| A2 | 独立上下文和结果回传 | 自动派独立规划/设计/测试/独占任务 |
| A3 | A2 + 并行 + 工作树/强制独占写入 | 自动并行代码波次 |
| A4 | A3 + 分配/监控/等待/取消/验收/集成 | 自动完成批准波次 |

## 一次开工授权

PRD、产品/架构、执行清单、共享契约、范围、预算、模型级别和任务边界批准后，询问一次开工。

记录：

```text
自动执行授权：已授权 / 未授权
授权范围：REQ/CARD/PAR、预算、模型、环境
需再次确认：新增范围、额外付费、登录授权、生产发布、数据/破坏性操作、共享契约变化、预算超限
```

授权后，A2-A4 在门禁通过时自动释放后续波次，不逐 Agent 或逐波重新问。只能启动真正可控制的工具；保存提示词不算派发。

## 工具和模型路由

| 任务 | 优先能力 | 推理/成本 |
| --- | --- | --- |
| 需求、产品、架构、复杂调试 | 能读项目/运行命令的总控 AI | 高；关键高风险极高 |
| 开发前开源参考与复用评估 | 能联网查 GitHub/官方文档/包生态并记录证据的当前 Agent；不可控外部工具才给完整提示词 | R1 中；R2/R3 高；R4 极高 |
| 单文件小改 | AI IDE 或当前 Agent | 中/高 |
| 跨文件功能 | 工作区/终端 AI + 测试 | 高 |
| UI 方向/设计系统 | 已检测设计专项能力 | 高，R3 独立复核 |
| 浏览器验证 | Playwright/浏览器/截图 | 中/高 |
| 安全/生产审查 | 安全专项 + 不同模型 | 极高用于发现/决策 |
| 部署 | 对应平台官方工具/CLI | 高，生产需批准 |
| 机械整理/文档格式 | 低成本模型或脚本 | 中 |

自主总控不是每项最强。设计、艺术、安全、浏览器、部署、领域和超级测评弱项派给更强专项工具；可控就自动启动，不可控才给用户一条完整提示词。

## 开源参考搜索执行规则

保存到 `docs/02-开源参考与复用评估.md`：

- 先从 PRD、产品框架和关键旅程抽取 `CAP-*` 能力，不按项目名泛搜。
- 当前 Agent 能控制网络搜索、GitHub、官方文档或包管理生态时，直接执行并记录查询入口、日期、证据和 unknown。
- 不能控制外部工具、需要登录授权、付费搜索、访问私有仓库或运行陌生代码时，停止在边界内，只给完整提示词或向用户说明需要授权。
- R1 只做快速检查或写跳过理由；R2-R4 必须在正式架构/编码前完成。
- 搜索结果不自动变成依赖；采用前必须经过许可证、维护、安全、供应链和总成本门禁。

用户界面只显示当前动作：

```markdown
### 当前步骤：STEP 5 - 开发前复用评估
- 已完成：需求已确认，已列出需要解决的能力。
- 现在要做：搜索并比较可参考或可复用的成熟项目、模板和组件。
- 执行工具：[GitHub/官方文档/包生态/当前 Agent 可控工具]
- AI 将执行：检查候选的功能匹配、技术栈、维护、许可证、安全、成本和退出方案。
- 产物保存到：[PROJECT_ROOT]\docs\02-开源参考与复用评估.md
- 完成标志：每个候选都有真实 URL、许可证、版本/commit、证据和明确决策。
- 需要你决定：仅付费、账号授权、许可证重大歧义、高风险执行或范围变化。
```

## 纵向功能卡

每张卡只交付一个用户可感知闭环：

```markdown
### CARD-001 - [名称]
- 关联 REQ / 优先级 / 波次：
- 用户任务与业务价值：
- 前置依赖与冻结契约版本：
- 输入、输出、规则、权限：
- 正常/空/无效/重复/失败/恢复：
- 数据/API/页面或命令：
- 允许修改 / 禁止修改：
- 目标代码和文档绝对路径：
- 测试与真实验收步骤：
- 完成证据 / 提交 / 审查人：
```

不要横向拆成“先全部数据库、再全部 API、再全部页面”。共享基础由 Wave 0 冻结，功能卡纵向完成。

## 并行资格

同时满足才并行：

- PRD/架构和共享契约批准。
- 至少两个任务无决定/数据/API/文件依赖。
- 每个任务有独占目录/文件或分支/工作树。
- 输出契约、路径、测试、预算、超时和失败接手人明确。
- 总控有能力验收和逐个集成。

数据库迁移、认证权限、共享 API/类型/路由/组件接口、环境和生产变更默认顺序。

## 自动波次

1. Wave 0：总控完成共享基础和契约。
2. 创建 `docs/18-并行协作计划.md` 和每个 `PAR-*` 交付记录。
3. A2-A4 自动创建全部就绪工作者；A0/A1 顺序或只读外派。
4. 用户只看状态板；完整提示词保存 `docs/并行任务/第N波-派发提示词.md`。
5. 总控监控/等待；真实启动才标 `执行中`。
6. 返回后检查路径、范围、契约、提交和证据；越界/无证据拒收。
7. 逐个合并，每次运行受影响测试，最后跑连接后的关键旅程。
8. 更新 `docs/19-并行结果汇总.md` 和 `docs/08-总装集成.md`。
9. 释放依赖满足的下一波。

超时、超预算、越界、无证据或要求改共享契约时，停止该工作者，标记阻塞，窄范围重试一次或降级总控顺序接手。不能留下看不见的后台依赖。

## 跨 AI 交接

每个外派提示词必须自足：

```text
打开：[实际检测工具]
项目/波次/PAR/CARD：[名称]
先读取：[项目路径索引、状态、执行清单、PRD、架构、任务记录绝对路径]
只完成：[一个目标]
允许修改：[绝对范围]
禁止修改：[共享契约和他人范围]
文档交付：[D:\...\PAR-XXX-任务与交付.md]
代码交付：[工作树/分支/目录]
完成标准：[测试/预览/结果]
回报：[内容、路径、提交、证据、限制/阻塞]
```

用户无需拼提示词。当前 Agent 能启动时直接启动；不能启动时才让用户复制这一条。

## 状态与可见反馈

任务状态：`待选择 / 待批准 / 执行中 / 已派发 / 工具阻塞 / 待验证 / 已验证`。

每个真实状态变化向用户报告工具、任务、保存路径和下一动作。长任务使用平台状态/等待能力，不创建后沉默。

总控唯一可写：项目状态、路径索引、执行清单、决策、追踪、总装、最终审查和合并决定。工作者不得改这些文件。

## 卡片审查

卡片完成后立即检查：范围/REQ、业务规则、权限/数据、安全、项目惯例、测试、真实运行、Git diff、提交、文档和下游契约。未通过就修当前卡，不把问题留到总装。
