# 09 AI 产品专项

## 目标

模型、提示词、Skill、RAG 或 Agent 不是完整产品。AI 能力必须服务具体用户任务，并有上下文、工具权限、输出约束、评估、成本和人工兜底。

## 五层方案

### 1. 用户任务层

- 谁在何时要完成什么结果？
- AI 比当前方法改善哪个可测指标？
- 哪些决定必须由人保留？

### 2. 知识与上下文层

- 输入、历史、用户偏好、业务规则、知识库和实时数据来自哪里？
- 来源、版本、权限、时效、隐私、长度和缺失如何处理？
- 不同用户/租户上下文是否隔离？

### 3. 模型与能力层

- 分类、抽取、生成、搜索、视觉、语音、代码或推理中真正需要什么？
- 用最便宜的足够模型；关键决定/审查才提高推理。
- 当前模型/API 能力、限制、价格和地区可用性查官方来源。
- 提示词/模型更换有版本、回归集和回滚。

### 4. 工具与行动层

- 每个工具的输入/输出、权限、允许对象、速率、超时、重试、幂等和审计。
- 读操作与写/付款/删除/发布分离；高风险行动先预览并人工确认。
- Agent 不能通过提示词绕过服务端授权和业务规则。
- 子 Agent 受 A0-A4、任务锁、路径和预算约束。

### 5. 产品与治理层

- 输出格式、引用/来源、置信/未知、可编辑、审批和人工接管。
- 有害/错误/敏感输出处理，申诉和反馈。
- 延迟、失败、降级到非 AI/人工流程。
- 每次任务模型/API 成本、配额、缓存和停用阈值。
- 日志不含完整敏感输入/密钥；保存和删除策略透明。

## AI 功能契约

为每条 `AI-FLOW-*` 写：

```markdown
### AI-FLOW-001 - [任务]
- 关联 REQ / 用户结果：
- 输入、上下文和来源/权限：
- 模型/工具及选择理由：
- 提示词/结构化输出版本：
- 成功、不可接受和未知结果：
- 自动校验/业务规则：
- 人工复核/接管：
- 超时、失败、降级和重试：
- 隐私、日志、保存和删除：
- 延迟/单次成本/额度上限：
- 评估集、阈值和证据：
```

## 评估而不是主观感觉

建立代表性评估集：正常、模糊、缺信息、极端长度、恶意/注入、权限、敏感、工具失败和高价值真实样本。

按任务选指标：正确/完整、结构合法、引用准确、幻觉/拒答、人工通过率、任务完成率、延迟、成本和安全事件。

发布门禁：

- 盲测当前版本与基线/替代，不只挑好例子。
- 阈值与交付等级匹配；高风险输出必须人工审核。
- 模型/提示词/RAG/工具变化自动跑回归集。
- 记录失败样本和决定，不为追分污染评估集。

## RAG/知识库

- 先证明搜索/规则/结构化数据库不够，再用向量检索。
- 文档来源、许可、版本、切分、元数据、权限和删除同步清楚。
- 回答显示来源；无足够证据时说不知道。
- 租户/用户权限在检索前过滤，不仅生成后过滤。
- 更新、失效、重建、成本和质量监控可操作。

## Agent 自动化

- 先用固定工作流解决确定流程；只有步骤需要动态选择时才用 Agent。
- 计划、行动、观察、停止条件、最大轮次、预算和人工接管明确。
- 工具结果视为不可信输入，防提示注入和越权。
- 写操作有确认/审批、幂等、审计和补偿。
- 自动分发不等于允许无限递归创建 Agent。

## AI 产品门禁

- AI 对用户结果有明确增益，不是营销标签。
- 上下文/权限/来源、工具边界和输出约束完整。
- 有代表性评估集、阈值、失败/降级和人工兜底。
- 单次和月度成本在批准范围。
- 安全、隐私、日志、数据生命周期和供应商退出路径明确。
- 用户知道 AI 的限制，能核验、修改、撤销和求助。
