# 06 测试、测评与完整交付

## 目标

用真实证据证明产品完成，而不是“代码能构建”或“页面看起来不错”。质量分开发中、集成后和交付前三层，避免重复审查。

## 第一层：卡片审查

每张功能卡完成立即验证：

- 与 `REQ-*`、范围和架构一致，无 CAND 偷渡。
- 业务规则、权限、数据所有权和状态正确。
- 正常、边界、失败、恢复和回归测试与风险匹配。
- UI 控件/状态和真实浏览器/API/命令结果成立。
- 修改只在允许范围，依赖/迁移/配置有记录。
- Git diff、提交和交付记录可追踪。

未通过修当前卡，不把已知问题留到最后。

## 总装集成

全部 MVP 卡通过后创建 `docs/08-总装集成.md`：

- 入口、路由、导航、共享状态和用户会话。
- 前端与 API、后端规则、数据库/文件、第三方/任务/通知。
- 权限、错误、重试、配置、日志和运营后台。
- 逐个合并提交和测试结果。
- 用真实或代表性数据完成“进入 -> 操作 -> 结果 -> 恢复/继续”的主旅程。

总装失败返回责任卡或共享契约，不在集成层堆临时补丁。

## 第二层：成熟产品审查

创建 `docs/09-成熟产品审查.md`，覆盖：

| 维度 | 必须验证 |
| --- | --- |
| 产品/范围 | 用户价值、完整生命周期、REQ/不做范围、无候选越界 |
| 前端/体验 | 真实内容、关键路径、状态、响应式、无障碍、兼容、设计双审 |
| 后端规则 | 状态、权限、幂等、并发、错误恢复、第三方失败 |
| 数据 | 所有权、一致性、迁移、备份恢复、导入导出、删除、审计 |
| 契约 | API/类型/模块/版本/校验/超时/重试/依赖未漂移 |
| 安全隐私 | 认证授权、越权、注入、XSS/CSRF、密钥、敏感数据、滥用 |
| 性能可靠性 | 代表性容量、延迟、资源、长任务、故障、恢复和降级 |
| 测试回归 | 单元/集成/E2E、正常/边界/失败、平台、迁移/升级 |
| 运维发布 | 环境、配置、日志、监控、告警、备份、回滚、支持 |
| 成本交付 | 实际成本、安装/开通、授权/套餐、文档、资产和支持边界 |

发现写 `REV-*`、严重度、证据、关联 REQ/模块、影响、修复工具/路径和复验。

总控先判断是缺陷、需求缺口、范围变更、架构问题、设计问题还是运营问题，再派正确工具修复，不让审查 Agent 顺手乱改。

## 发布前体检

任何公开/生产发布前创建 `docs/22-发布前体检.md`，至少检查：

1. 开发/测试/生产数据库、密钥、域名和配置分离；生产调试关闭。
2. 密钥未硬编码、未进 Git、未进日志或前端。
3. 正式测试全绿；失败项不带病上线。
4. 临时接口、调试输出、假数据、测试账号和无权限接口清理。
5. 越权、注入、敏感返回、上传、登录/短信/支付/下单限流。
6. 登录、权限、金额和重要数据变更有结构化日志，日志不含敏感值。
7. 大量图片/音视频走对象存储，保存链接；迁移/清理有方案。
8. Web 主流浏览器、手机、普通设备和前端性能；动效有必要且支持减少动态。
9. 上线数据干净，迁移、备份恢复、监控、告警和回滚已验证。
10. 域名、证书、第三方账号、配额、实际持续成本和责任人明确。

先检查并列问题，用户批准后修复。不得因为体检自动改生产、删数据、轮换密钥或部署。

## 严重度

- P0：数据损坏/泄露、严重安全、核心不可用、无法安装/启动或关键交付缺失。必须修。
- P1：核心错误、重要权限/恢复/兼容/体验/文档误导。修复或所有者明确接受。
- P2：明显影响效率、审美、维护、成本但不阻断。定版本和负责人。
- P3：偏好/可选优化。进入 CAND。

风险只能由项目所有者/客户接受，AI 不静默接受。

## 第三层：超级测评

成熟审查修复后，由非主要开发 Agent 作为超级测评师，创建 `docs/09-超级测评报告.md`。

测评基线读取项目索引、PRD、追踪、产品、架构、功能卡、控件、设计系统、测试、总装、风险和发布体检。

测评矩阵：

| TEST-ID | 角色/场景 | REQ/UI-CTRL | 前置 | 真实输入与操作 | 预期 | 证据 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |

执行：

1. 黑盒新用户：无开发知识、无缓存/旧状态，完成首次价值。
2. 熟练用户：重复、搜索、批量、继续、撤销和效率。
3. 管理/运营：配置、审核、用户、异常、查询、补偿和日志。
4. 功能逐项：每个已交付 REQ/UI-CTRL 的入口、规则、权限、结果和状态。
5. 全栈：页面、API、规则、数据库/文件、任务、通知和第三方组合。
6. 边界：空/错/重复/无权限/断网/超时/大数据/低性能/第三方失败。
7. 工程：干净安装、启动、构建、测试、环境、备份恢复、回滚和升级。
8. 交付：URL/安装包/源码、版本、账号资产、配置、数据、文档和限制。

使用真实或代表性数据，记录命令、请求、日志、数据结果、截图/视频或复现步骤。测评发现先回总控分类，不能直接改。

全部计划执行、P0 清零、P1 处理、核心用户/管理/安装升级/异常/交付路径有证据，才写“测评通过”。

## 自动生成手册

超级测评首次通过后自动生成：

### `docs/12-产品使用手册.md`

- 产品/版本、适用人群、用途和边界。
- 系统/设备/浏览器/账号/权限要求。
- 安装/开通、首次启动、授权和配置。
- 用真实示例逐步完成核心工作流：打开哪里、点击/输入什么、看到什么、成功标志。
- 管理员/运营配置、审核、用户、数据、日志和异常。
- 导入导出、备份恢复、升级迁移、卸载/停止和数据处理。
- 常见错误、用户处理、联系支持条件。
- 限制、安全、隐私、费用/额度、支持和验证日期。

不得写不存在的按钮/功能或敏感密钥。

## 手册反向复测

不了解实现细节的测评角色只按手册完成：安装/打开、一个核心用户流程、适用的管理员流程、一个错误恢复、适用的升级/导出/备份。任何名称、路径、步骤、结果不符，修产品或文档后重测，证据追加超级测评报告。

## 部署路由

根据项目选已检测工具：静态前端/全栈平台、后端服务、容器、桌面安装包、CLI 包管理器等。部署前说明账号、费用、域名、环境变量、数据、监控和回滚；生产动作单独批准。

完成信号：目标 URL/安装包/发布物可用，手机/目标系统能打开，生产冒烟通过，回滚/恢复责任明确。

## 完整交付

创建 `docs/13-完成品文档.md`：产品/版本/等级/验收、URL/命令/安装包/校验、源码与提交、部署环境、构建测试测评证据、包含/不含、已接受风险、账号/数据/许可/支持/升级边界。

更新 `项目总文档.md` 和全局索引。客户项目另完成资产移交、支持截止、剩余款项/风险和签收。

未通过手册反测、缺适用关键资产、P0 未清或 P1 未决定，不得标记完整交付。
